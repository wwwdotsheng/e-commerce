## 跨模块规则

- 订单生命周期定义何时关单，库存和优惠券 Spec 分别定义资源如何返还。订单验收引用两份规则，并核对关单、返库存和退券的整体提交或回滚结果。
- 支付 Spec 定义订单支付引发的资金和订单状态变化，余额 Spec 定义余额查询和充值。两个场景分别验证重复请求只产生一次对应的资金变动。
- 退款 Spec 要求正金额退款成功时，商家扣减、买家入账和可追溯流水一起生效。零元退款以退款记录留痕，已支付订单退款成功后不返还库存。商家余额不足时由后台标记失败。技术细节见[站内钱包退款设计](../design/order-refund-wallet-design.md)。

建议按账号与会话、商品与库存及优惠券、订单与钱包支付及退款的顺序整理。每份 Spec 写清可观察结果和验收条件，Redis 键结构、MQ 拓扑、Worker 领取方式和数据库迁移等技术细节由对应设计文档维护。
