# <功能名称>

## 背景与目标

描述什么情况下会出现问题、影响哪些用户，以及用户期望看到什么结果。

## 本次范围

说明本次处理的操作、角色、入口和业务状态。容易产生歧义时，明确本次交付的边界。

涉及 HTTP 接口时，列出新增或修改的请求方法和路径，以及各角色允许执行的操作。

## 验收标准

每项写明初始条件、执行操作、可观察的结果和最终数据。涉及 HTTP 时，写明 HTTP 状态码、业务错误码和关键响应字段。涉及异步处理时，分别写明请求返回时和后台处理完成后的可观察结果，并注明如何确认处理完成。

- [ ] 正常场景：给定 `<初始条件>`，执行 `<操作>`，应得到 `<响应或可观察结果>`，最终数据为 `<预期状态>`。
- [ ] 关键失败场景：给定 `<失败条件>`，执行 `<操作>`，应得到 `<错误结果>`，相关数据为 `<保留、回滚或更新后的状态>`。
- [ ] 重复或并发场景（适用时）：给定 `<初始条件>`，重复或同时执行 `<操作>`，各次调用应得到 `<允许的结果>`，最终留下 `<预期记录和状态>`。

## 待确认
