# 订单退款

## 背景与目标

订单使用站内钱包支付时，买家余额减少，商家余额增加。原模拟渠道退款只更新退款和订单状态。站内钱包退款需要把原订单款项实际退回买家。

## 本次范围

- 适用于使用站内钱包支付的订单，退款金额取原订单的实付金额，支持全额退款。
- 买家首次申请通过校验后，接口立即返回 `pending`，当前流程无需商家同意。资金条件由后台处理，买家通过订单详情查询结果。退款进入最终失败状态 `failed` 时，订单详情的 `refund.failure_reason` 返回「本次退款未完成」。买家可见的响应和时间线不得暴露商家余额或余额不足。
- 正金额退款成功时，从该订单的商家钱包扣减退款金额，并向该订单的买家钱包增加同等金额。双方余额、可追溯的退款流水、退款成功和订单已退款必须一起生效。退款流水可按退款 ID 关联到原订单及双方钱包。
- 零元退款保留退款记录并更新订单状态，双方余额保持原值，不写入 `wallet_logs`。
- 商家余额不足以全额退款时，后台直接将退款标记为 `failed`。重复申请返回同一笔退款记录。
- 本期已支付订单退款成功后不返还库存，优惠券按现有规则退回。退货收货与入库后的库存返还留待独立需求定义。
- 已入队且未结束的退款任务到期后也按站内钱包退款处理。已结束的退款不重新执行。

## 验收标准

- [ ] 给定实付 100 元且尚未申请退款的已支付订单，商家余额为 150 元、买家余额为 20 元。买家申请退款时接口返回 HTTP 200、业务码 `000000` 和 `pending`。后台完成后，订单详情显示退款 `succeeded`、订单已退款，商家余额为 50 元、买家余额为 120 元。
- [ ] 同一订单重复或并发申请时，各次请求得到同一个退款 ID。后台重复执行同一笔正金额退款时，资金只退回一次，按退款 ID 查询只得到一组对应流水。
- [ ] 零元订单退款成功时，双方余额保持原值，退款记录为 `succeeded`、订单已退款，`wallet_logs` 中没有这笔退款的流水。
- [ ] 已支付订单退款成功后，商品库存等于退款处理前的库存，优惠券按现有规则退回。
- [ ] 退款处理失败时，双方余额保持处理前的值，订单保持已支付，且未留下成功退款流水。最终进入 `failed` 时，买家查询订单详情，`refund.failure_reason` 为「本次退款未完成」，响应和时间线中均无商家余额或余额不足信息。
- [ ] 旧渠道任务尚未结束时，后台到期执行与新任务相同的钱包退款。已经结束的旧退款余额和流水保持原值。

## 商家同意退款

后续在商家端增加「同意退款」操作。单独确认哪些申请需要商家审核、谁能同意、同意后何时启动退款，以及未同意或超时如何处理。

## 退款状态

- 首次受理返回 `pending`。后台完成后状态为 `succeeded` 或 `failed`。
- 退款成功时写入 `refunded_at`，并将订单从已支付更新为已退款。退款失败时订单保持已支付。
- 数据库错误回滚本次处理，任务保留供后续扫描。

## 接口

| 接口 | 行为 |
|---|---|
| `POST /api/v1/order/{id}/refund` | 校验买家/归属/已支付，事务内写 refunds + refund_jobs，立即返回 `pending`；重复/并发申请返回同一条记录 |
| `GET /api/v1/order/{id}` | 订单详情；`refund` 只读返回当前退款状态，`timeline` 返回订单+退款的状态时间线，无退款时 refund 为 null |

错误码：

- `A00001` 参数非法
- `A00002` 订单/退款不存在或不属于当前用户
- `A02100` 非买家
- `A05105` 订单当前状态不可退款
