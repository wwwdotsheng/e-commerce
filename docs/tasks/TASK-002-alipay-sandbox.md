# TASK-002 支付宝沙箱支付与原路退款

- **状态：** 暂缓接入
- **关联任务：** [TASK-001 站内钱包订单退款](active/TASK-001-wallet-refund.md)

## 1. 任务概述

恢复接入时，建议先在支付宝沙箱跑通一笔订单从网页收银台支付到原交易退款的闭环。站内钱包订单继续按[订单退款 Spec](../requirements/order-refund.md)处理。支付宝退款需要关联该渠道的原支付交易。

本方案先验证单个沙箱应用下的交易闭环。钱包充值、生产收款、商家分账及结算另行确认。

## 2. 技术实施方案（Plan）

1. 候选依赖为第三方 Go SDK [smartwalle/alipay/v3](https://github.com/smartwalle/alipay)。它提供网页支付、支付查询、退款、退款查询和通知验签。支付宝开放平台的 [SDK 目录](https://open.alipay.com/tool)没有列出国内开放平台 Go SDK。批准后再确认并固定版本，通过配置启用沙箱网关，凭据由环境或密钥管理提供。
2. 为支付宝支付持久化支付渠道、商户订单号、支付宝交易号、金额和状态。网页返回页只展示进度。服务端在验签并核对应用、商户、订单、金额和交易状态后，幂等确认支付。异步通知缺失时通过主动查询确认。
3. 同一订单只能确认一次支付。方案评审时明确支付宝支付待确认期间如何限制再次发起钱包支付，以及超时关单前如何查询和关闭支付宝交易，避免已支付订单释放库存。支付宝网络请求在数据库事务外执行。
4. 退款按原支付渠道分流。支付宝订单使用原交易号和稳定的退款请求号调用 `alipay.trade.refund`，结果不明确时查询同一笔退款。渠道确认成功后更新本地退款及订单状态。沙箱支付宝订单的收退款都由沙箱交易体现，站内钱包保持原值。

参考[支付宝沙箱联调说明](https://open.alipay.com/paymentServicer/paymentProvider.htm)及[支付宝支付与退款接入指南](https://aipay.alipay.com/docs/vibe-pay/ai-web-app-payment-qianyi/ai-web-app-payment-integration-guide.html)。

- [ ] 批准 SDK 依赖、支付记录模型、支付确认及超时关单方案。

## 3. 开发任务（Tasks）

- [ ] **确认范围与契约**。确定支付入口、状态变更与超时规则，记录批准结果。验证方式为评审支付与退款状态转换，确认同一订单只确认一次支付。
- [ ] **跑通沙箱支付**。生成收银台请求，通过通知或查询确认订单已支付。验证方式为核对沙箱交易、金额与本地订单，并检查重复通知的结果。
- [ ] **跑通沙箱退款**。从原支付宝交易退回，并能查询结果。验证方式为核对原交易、退款请求号与本地状态，以及重复请求和结果不明时的行为。
